# 项目实验台 · 钉钉登录配置

## 目标

员工使用本企业钉钉账号登录项目实验台。认证成功后，项目成员、任务负责人、审核人及后续钉钉通知接收人可以引用同一员工身份。

当前实现采用钉钉 OAuth 2.0 授权码流程：浏览器跳转到钉钉登录页，服务端用一次性授权码换取用户访问凭证，再读取当前用户资料。应用密钥、用户访问凭证和项目会话均不暴露给浏览器 JavaScript。

## 一、创建企业内部应用

在[钉钉开发者后台](https://open-dev.dingtalk.com/)选择当前企业，创建企业内部应用。记录应用的 Client ID 和 Client Secret，并取得企业 Corp ID。

在应用权限管理中申请个人权限：

```text
Contact.User.Read
```

在登录与分享或 OAuth 配置中登记本地回调地址，地址必须和服务配置逐字一致：

```text
http://127.0.0.1:4317/api/auth/dingtalk/callback
```

开发者后台若要求发布应用版本，应先在测试范围内发布，只纳入参与本地预演的员工。

## 二、配置本地服务

仓库根目录默认不保存真实凭据。首次配置时创建 `.env`，建议权限设为仅当前用户可读写：

```bash
cd /Users/pechen/AI/钉钉应用
cp .env.example .env
chmod 600 .env
```

编辑 `.env` 中以下字段：

```dotenv
AUTH_MODE=dingtalk
DINGTALK_CLIENT_ID=<应用 Client ID>
DINGTALK_CLIENT_SECRET=<应用 Client Secret>
DINGTALK_CORP_ID=<企业 Corp ID>
DINGTALK_REDIRECT_URI=http://127.0.0.1:4317/api/auth/dingtalk/callback
DINGTALK_BOOTSTRAP_FIRST_ADMIN=true
AUTH_SESSION_DAYS=7
```

启动服务：

```bash
npm run db
npm run build
npm start
```

打开 <http://127.0.0.1:4317>，点击“使用钉钉账号登录”，完成授权后应返回项目实验台。

## 三、首位主管与后续员工

全新数据库中启用 `DINGTALK_BOOTSTRAP_FIRST_ADMIN=true` 时，第一个通过 Corp ID 校验的员工会绑定预置成员 `supervisor`，用于项目审核和初始化。首次登录确认无误后，将该值改为 `false` 并重启服务。

也可以预先配置 `DINGTALK_ADMIN_UNION_ID` 指定主管的 Union ID。后续首次登录的员工会自动创建普通项目成员；再次登录会更新昵称、Open ID、Corp ID 和头像，不会重复创建成员。

若数据库已经产生过登录用户，重新打开首位主管开关不会把下一位员工提升为主管。需要变更既有人员角色时，应使用后续提供的管理员界面或经过审计的数据迁移，不直接修改浏览器身份。

## 四、验证清单

1. 未登录访问 `/api/state` 返回 401。
2. 登录入口跳转到 `https://login.dingtalk.com/oauth2/auth`，参数包含 `response_type=code`、`scope=openid corpid` 和随机 `state`。
3. 钉钉授权后回到本地地址，页面显示当前员工姓名。
4. 非本企业 Corp ID 会被拒绝。
5. 浏览器 Cookie 为 HttpOnly、SameSite=Lax；部署 HTTPS 后自动添加 Secure。
6. 退出登录后旧会话不能再次访问项目数据。
7. `procli` 只有完成本企业钉钉个人授权并携带个人 CLI Token，才能访问业务接口。

自动验证命令：

```bash
npm run check
npm test
npm run verify:auth
```

`verify:auth` 使用本地模拟钉钉接口和临时数据库，不读取真实 Client Secret，也不修改日常项目库。

## 安全与数据边界

- PostgreSQL 只保存用户 Union ID、Open ID、Corp ID、姓名、头像地址和项目成员映射。
- 钉钉 User Access Token 只在登录回调期间使用，不写入数据库。
- 项目会话随机值只保存在浏览器；数据库保存其 SHA-256 摘要。
- Client Secret、个人 CLI Token 和 `.env` 不提交 Git。
- `AUTH_MODE=development` 允许请求头模拟角色，只用于隔离测试。
- 本地 HTTP 仅用于单机开发。开放给局域网员工或迁移 NAS 时，应使用企业内网域名和 HTTPS，并把同一 HTTPS 回调地址登记到钉钉应用。
