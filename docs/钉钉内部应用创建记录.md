# SealSeek 项目管理 · 钉钉内部应用创建记录

## 目标

为“SealSeek 项目管理”建立一个长期复用的企业内部应用，统一承载以下能力：

- 企业员工使用钉钉账号登录项目管理系统。
- 钉钉员工身份与项目成员、任务负责人、审核人建立稳定映射。
- 后续向任务负责人发送任务到达、节点完成、审核结果和阻塞提醒。
- 本地开发完成后迁移到 NAS，沿用同一个企业内部应用并更新正式 HTTPS 回调地址。

## 2026-09-15 实施记录

### 1. CLI 能力确认

官方 DingTalk Workspace CLI `dws` 已登录当前企业，能够管理开放平台企业内部应用。本机安装的是签名稳定版 `v1.0.61`，构建提交为 `50eb73a0`，`dws upgrade --check` 确认它与 2026-08-31 发布的最新稳定版一致。macOS 二进制使用 Taobao (China) Software CO.,LTD 的 Developer ID 签名。

与本次任务有关的稳定命令包括：

```bash
dws devapp +list
dws devapp +create
dws devapp +get
dws devapp +credentials-get
dws devapp +permission-list
dws dev app permission add
dws dev app security config
```

创建应用属于真实写操作，CLI 要求用户确认后使用 `--yes`。读取应用凭证时，返回的 Client Secret 只能直接进入本机私有配置，不能进入日志、文档或聊天正文。

### 2. 创建前盘点

创建前完整查询了当前企业的企业内部应用列表：共有 10 个，其中 7 个名为“小钉”，其余为“店铺数据自动同步”“Codex助手”和“墨子”。没有名为“SealSeek 项目管理”的现有应用，因此不存在同名重复创建风险。

7 个“小钉”均配置了在线机器人。本人创建的“小钉”也处于机器人在线状态，不能仅凭名称相同就认定为空应用或直接改作项目管理用途。其他三个具名应用都有明确业务用途。

### 3. 应用创建

执行了以下创建意图：

```text
应用名：SealSeek项目管理
描述：企业内部项目看板、项目 Wiki、Agent 协作与钉钉任务通知的统一应用入口
```

CLI 首次使用带空格的名称“SealSeek 项目管理”时，钉钉开放平台返回业务错误 `67009`。开发者后台网页给出了完整校验提示：应用名称只能由中文、英文字母和阿拉伯数字组成，空格不符合命名规则。用于复核该次 CLI 失败的 Trace ID：

```text
2106d98117894541175013481e08b8
```

改用符合规则的名称 `SealSeek项目管理` 后，网页创建成功。CLI 按返回的 unifiedAppId 回读确认：创建人为陈金龙，应用状态为 `normal`，版本状态为 `INIT`。

### 4. 权限与安全配置

本次登录只申请了个人权限 `Contact.User.Read`。CLI 返回 `applied=true`，没有被拒绝的权限点，也没有附带通讯录管理、消息、机器人等权限。

登录重定向地址配置为：

```text
http://127.0.0.1:4317/api/auth/dingtalk/callback
```

CLI 写后回读确认 `changedFields=["redirectUrls"]`。新应用没有启用机器人、网页工作台入口和其他应用能力。

### 5. 凭据落盘

使用 `scripts/configure-dingtalk-credentials.ts` 从官方 CLI 读取指定 unifiedAppId 的凭据。脚本执行以下安全步骤：

1. 验证返回的 unifiedAppId 与目标完全一致。
2. 在改写前为 `.env` 创建独立恢复备份。
3. 将 Client ID 和 Client Secret 原子写入本机 `.env`。
4. 首次配置时生成独立的 Agent API Token。
5. 将 `.env` 和备份权限设为 `600`。
6. 输出只包含 Client ID 和配置状态，不打印任何 Secret 或 Token。

`.env`、`.env.backup-*` 和 `.env.tmp-*` 均被 Git 忽略。

### 6. 真实 OAuth 验收

本地服务重启后，`/api/auth/session` 显示钉钉认证已配置。通过电商浏览器固定 CDP `http://127.0.0.1:9223` 完成真实登录：

1. 本地页面跳转到标题为“SealSeek项目管理”的钉钉统一身份认证页。
2. OAuth 参数包含正确 Client ID、回调地址、随机 state、`response_type=code` 和 `scope=openid corpid`。
3. 明确选择“苏州东轩塑料制品有限公司”并同意读取基本身份。
4. 钉钉回调成功返回本地项目页，页面显示“钉钉身份已验证”和员工姓名。
5. PostgreSQL 中的员工身份映射指向预置成员 `supervisor`。
6. 携带浏览器会话访问项目数据返回 200。
7. 使用独立 Agent Bearer Token 调用 `projectctl project list` 成功。

首位主管初始化完成后，`DINGTALK_BOOTSTRAP_FIRST_ADMIN` 已关闭，后续首次登录员工将按普通成员创建。

### 8. NAS 员工预演配置

2026-09-15 将登录实现同步到 GitHub 与 UGREEN NAS。钉钉应用安全配置同时保留本地回调和 NAS 局域网回调；`dws` 写后返回 `changedFields=["redirectUrls"]`。

NAS 运行时配置保存在代码仓库外的 `/volume1/docker/agent-project-lab/config/runtime.env`，权限为 `600`。其中包含数据库密码、钉钉应用凭据、Corp ID、NAS 回调地址和独立 Agent Token；GitHub 仓库只保存变量名与部署定义。应用端口对企业局域网开放为 `192.168.100.172:14317`。

使用电商浏览器从 NAS 地址完成了一次真实 OAuth 验收：登录入口生成 NAS 回调，钉钉统一身份认证显示正确应用名，选择目标企业后成功返回项目看板。NAS PostgreSQL 中的首个登录身份按预置 Union ID 绑定到 `supervisor`，不依赖员工登录顺序。

本次是企业内网预演。正式长期使用时，将入口升级为 NAS 反向代理下的 HTTPS 企业内网域名，并在钉钉应用中登记完全一致的 HTTPS 回调地址。

先使用固定入口启动并验证电商浏览器：

```bash

```


## 标准配置流程

以后创建同类应用时按以下顺序配置：

1. 用 unifiedAppId 精确回读名称、描述、状态和创建人。
2. 读取 Client ID 和 Client Secret；Client ID 写入实施记录，Client Secret 只写入权限为 `600` 的本机 `.env`。
3. 申请个人权限 `Contact.User.Read`，然后回读权限状态。
4. 配置登录重定向地址 `http://127.0.0.1:4317/api/auth/dingtalk/callback`。
5. 若新增能力属于版本生效项，再创建应用版本并预检是否需要审批；涉及审批人选择时由管理员本人决定。
6. 用真实钉钉账号完成一次本地 OAuth 登录，验证 Corp ID、员工映射、HttpOnly 会话和退出登录。
7. 登录初始化完成后关闭“首位员工自动成为主管”的开关。

## 复用原则

- 一个企业内部应用可以服务同一企业的所有员工，不需要为每个员工创建应用。
- 本地、NAS 和未来服务器可共用同一个应用，但各环境应使用已登记的准确回调地址。
- 登录身份和后续消息通知可以复用同一员工映射，但每项新增 OpenAPI 能力仍按最小权限单独申请。
- 测试与生产只有在需要严格隔离密钥、权限、审计或发布节奏时，才有必要拆成两个应用。
- 变更应用前始终先用 unifiedAppId 回读现状；不要仅按应用名选择写操作目标。
- 应用名称只使用中文、英文字母和阿拉伯数字，不包含空格或其他符号。
