# 本地 Agent 项目管理实验台

## 目标

用一个本地运行的系统验证：Agent 按企业 SOP 创建商品项目、执行具体业务工作、沉淀项目知识、更新任务并交给人审核，是否降低维护成本并提高交付效率。

第一版覆盖项目看板与项目 Wiki 两个核心场景。页面供人浏览、修改和审核；CLI 与 HTTP API 供 Agent 读写。两种入口使用相同的状态规则。

## 工作闭环

创建项目 → 根据商品生命周期生成七个阶段与依赖任务 → Agent 读取任务与 Wiki → 在 Agent 宿主中执行业务 Skill → 写入结论与附件 → 提交审核 → 主管通过或退回 → 自动生成下游负责人通知。

任务状态为待开始、进行中、待审核、已完成、已阻塞。阶段表示业务归属，状态表示实际执行进度。前置任务完成才可开始后续工作；审核通过需由指定审核人执行；退回和阻塞记录原因。

## 数据与结构

- PostgreSQL 保存项目、任务、成员、运行记录、审计、通知、Wiki 元数据与耗时记录。初稿使用单行 JSONB 状态与行锁串行化写操作。
- 项目独立目录保存 Markdown、附件及历史版本，支持不依赖页面读取。
- 文档按项目首页、立项、市场、需求人群、视觉、推广、售后、复盘组织。结论应标注输入依据、时间范围、分析方法、限制与下一步。
- CLI 提供结构化 JSON、可发现能力、错误码、幂等键与 dry-run。Wiki 和任务写入进行版本校验。
- Agent 运行记录描述实际执行的 Skill、版本、输入、输出与质量说明；模拟数据单独标识。

## 页面

左侧为商品项目列表。项目内含看板、Wiki、Agent 运行、活动记录、消息和提效验证。

看板按商品业务阶段分列，任务详情包含负责人、审核人、截止日、优先级、验收标准、依赖、Wiki 与附件。Wiki 支持 Markdown 编辑预览、全文关键词检索、历史查看。导出恢复保留任务、正文、附件、历史与操作记录。

## 提效验证

选定一项有明确交付标准的真实商品工作，记录人工基线耗时、Agent 执行耗时、人工纠正耗时与质量评价。对相同事项分别统计平均耗时；实际减少量与质量共同决定效果。演示数据用于验证软件流程，不用于证明业务提效。

## 部署与迁移

本机使用独立 PostgreSQL 集群与回环地址监听，代码、数据库与项目文件位置分离。首次迁移可导出项目并在新环境恢复，恢复产生新项目标识；整机迁移则同时备份 PostgreSQL 与项目文件并保留原 ID。提供容器定义作为 NAS 部署起点。

正式多人上线前需配置身份认证、权限隔离、HTTPS、数据库密码、持久化备份、消息发送账号与监控，并完成 NAS 环境实测。开发机无需依赖公司网络。
